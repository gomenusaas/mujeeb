# MUJEEB · مجيب — customer app

The customer app from the Claude Design handoff (`project/MUJEEB App.dc.html`), built as a
mobile-first React + Vite + TypeScript web app. It opens in Arabic (RTL) and switches fully to English.

- **On a phone (≤ 520 px wide, or installed to the home screen):** runs full-screen and respects the notch
  and home-indicator safe areas. Safari → Share → *Add to Home Screen* installs it with its own icon.
- **On a desktop:** shows the design's 390 × 844 phone frame with the demo panel beside it
  (language switch and "Jump to screen" shortcuts).

## Run

```bash
cd app
npm install
npm run dev        # http://localhost:5173
npm run build      # type-check + production build into dist/
```

## Data: Supabase or bundled demo

The app reads its catalog (categories, companies, services, albums) from Supabase when
`VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` are set (copy `.env.example` to `.env.local`).
Without them, it uses the bundled demo data in `src/data/demo.json`, which matches the seed exactly.

Set up a Supabase project:

1. Run the files in `supabase/migrations/` in order (`20261109000000_customer_app.sql`, then
   `20261110000000_album_created_at.sql`), then `supabase/seed.sql`
   (SQL editor, or `supabase db push` + `psql -f supabase/seed.sql`).
2. In **Authentication → Providers**, turn on **Anonymous sign-ins**. The app signs the customer in
   anonymously, so row-level security can scope their records to them until real login exists.
3. Put the project URL and anon key in `.env.local`.

What goes to Supabase when it's configured:

| Action | Table / function |
|---|---|
| Quotation request (server-generated `MJB-RFQ-…` reference) | `quotation_requests` |
| Site-visit booking (`MJB-BK-…`, stored in UTC, entered in Asia/Muscat time) | `bookings` |
| Cancel booking / accept proposed time | `bookings` update / `accept_booking_reschedule()` |
| Accept / reject a quotation | `respond_to_quotation()` |
| Favorites | `customer_favorites` |
| Chat messages (one conversation per customer + company) | `conversations`, `messages` |

The database blocks new bookings and requests when the company or the platform has them turned off
(`platform_settings`, `companies.accepts_*`).

The migration, seed and policies were tested on Postgres 16 with a stub `auth` schema: anon can read
the catalog but can't write; customers only see their own rows; a customer can't confirm their own booking.

## What is still local or simulated

- The UI keeps the customer's quotations, bookings, chats and favorites in `localStorage`, starting
  from the demo history (3 requests, 3 bookings, 3 chats). Server writes are additional: the lists aren't read
  back from Supabase yet, because the demo history has no owner in the database.
- The company "reply" in chat is a canned message after 1.4 s; there is no provider inbox yet.
- **WhatsApp** opens `wa.me/<number>` and **Call** opens `tel:`. The demo numbers are fictional.
  Email, website, social links, *Download PDF*, Settings, Help and Sign out show a notice only.
- RFQ attachments use the device's file picker, but only the file names and sizes are kept; nothing is uploaded to storage yet.
- Promo banners, the map view and the service video use the design system's striped placeholders, as in the design.
- Booking dates are the next six days after today (Fridays skipped). Which slots are full is simulated.
- Photos load from Unsplash and fonts from Google Fonts, so the app needs a connection.

## Structure

```
src/ds/          Servly design-system components, ported 1:1 from the design bundle (+ RTL fixes)
src/ds/icons.ts  Lucide icons used by the app, inlined (generated by scripts/build-icons.mjs)
src/i18n/        All UI strings, Arabic + English
src/data/        Types, Supabase client and loaders, bundled demo data
src/app/         App state and navigation, shared view pieces, booking dates, mouse drag-scroll
src/screens/     Discover (home, categories, explore), Provider (listing, company, service, album),
                 Flows (quotation request, booking), Account (messages, chat, profile, quotes, bookings…)
supabase/        Migration and generated seed
scripts/         export-data (design data → demo.json), build-seed (demo.json → seed.sql), build-icons
```

To regenerate data after editing `project/mujeeb-data.js`:
`node scripts/export-data.mjs && node scripts/build-seed.mjs`.
